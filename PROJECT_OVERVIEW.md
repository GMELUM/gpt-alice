# GPT Alice — контекст разработки Mini 3

Обновлено: 2026-10-28. Это рабочая документация к текущему состоянию исходников. Параметры конкретной домашней сети, MAC-адрес, SSH private key и OAuth-токены сюда не записываются.

## Назначение и статус

GPT Alice — Rust-приложение, установленное на выкупленной Яндекс Станции Mini 3 после отвязки от облачной логики Яндекса. Оно предоставляет локальную веб-панель, управляет доступными функциями устройства и связывает голосовой поток с GPT-Live. Веб-панель рассчитана на доверенную локальную сеть и пока не имеет своей авторизации.

Фактически присутствуют: управление кольцом и часами-индикаторами, сцены переднего экрана, системная громкость/mute, Bluetooth, время/NTP, чтение кнопок и аппаратного mute, ChatGPT/Codex OAuth, голосовой звонок, журналирование, клиентский web search и структурированные действия устройства. Точное состояние проверяйте по коду и API: этот документ не заменяет live-проверку колонки.

## Архитектура

1. `src/main.rs` запускает Axum HTTP server и регистрирует маршруты.
2. `src/indicators.rs` управляет LED-кольцом и сегментами часов.
3. `src/runtime.rs` отвечает за input events, системную громкость/mute, Bluetooth, время, яркость/сцены и сохранение настроек.
4. `src/oauth.rs` реализует device-code OAuth, хранение/обновление токенов и статус авторизации.
5. `src/voice.rs` управляет GPT-Live сессией, логами, вызовом helper, распознаванием структурированных device actions, web-search делегацией и завершением звонка.
6. `src/web_search.rs` вызывает web search по Codex OAuth.
7. `native/gpt-live-host/` — отдельный Rust/WebRTC/CPAL процесс. Он получает команды через JSON Lines stdin/stdout, владеет аудио устройствами и не получает OAuth-токен.
8. `web/index.html` — встроенная локальная панель.

Основные HTTP пути: `/`, `/api/indicators`, `/api/runtime`, `/api/time`, `/api/display/face`, `/api/auth/status`, `/api/auth/start`, `/api/auth/logout`, `/api/voice`, `/api/voice/logs`, `/api/voice/toggle`. Остальные операции индикаторов доступны отдельными POST маршрутами, определёнными в `src/main.rs`.

### Управление голосовыми командами

Команды не должны извлекаться только локальными регулярными выражениями из пользовательской фразы. Модель/классификатор получает историю диалога и набор явных function tools, возвращает одно структурированное действие (`set_volume`, `adjust_volume`, `set_mute`, `set_clock_brightness`, `adjust_clock_brightness`, `set_bluetooth`, действия `get_*`, `end_call`). Rust валидирует аргументы, исполняет действие и озвучивает только подтверждённый результат. Запросы о состоянии также используют `get_*`, чтобы не отвечать по устаревшему контексту.

При ответе GPT-Live клиентской делегации передаётся её исходный `delegation_id`; результат не должен отправляться произвольным событием. Наблюдаемое GPT-Live соединение использует приватный endpoint `chatgpt.com/backend-api/codex/realtime/calls`; он может меняться и не является стабильным публичным контрактом. Ошибки в этом канале надо сопоставлять с журналом звонка и текущим API status.

Событие WebRTC peer `disconnected`/`failed` считается временным: мониторинг продолжает работать, команды/аудио могут оставаться активными. Только `closed` или фактическая остановка GPT-Live сессии переводит звонок в конечное состояние. Это сделано по наблюдению, что иногда WebRTC показывает потерю, хотя GPT продолжает отвечать.

## Mini 3 и установка

- Устройство — Яндекс Станция Mini 3, Linux/Buildroot, root доступ настроен отдельно от проекта.
- Приложение установлено в `/data/opt/gpt-alice/`, основной бинарник `gpt-alice`, аудио-помощник `gpt-live-host` должен лежать рядом.
- Автозапуск: `scripts/S99zzgpt-alice`, установленный как `/etc/init.d/S99zzgpt-alice`; логи процесса: `/data/opt/gpt-alice/server.log`.
- SSH через Dropbear использует порт 2222. IP и путь к ключу индивидуальны и не хранятся в документации.
- Фоновая сеть Wi-Fi/Bluetooth и аппаратные драйверы — системные службы. Не удалять их при сопровождении GPT Alice.
- Служба панели по умолчанию слушает `0.0.0.0:80`; доступа без авторизации достаточно только в изолированной домашней LAN.
- Настройки приложения хранятся в `/data/opt/gpt-alice/config.json`; OAuth-токены — в `auth.json` около исполняемого файла. На устройстве секретный файл получает права владельца (`0600`). Не копируйте его в проект/бэкапы общего доступа.

### Кнопки и аппаратные интерфейсы

- `/dev/input/event0`: GPIO, в том числе `KEY_MUTE` и switch `SW_MUTE_DEVICE`.
- `/dev/input/event1`: сенсорная панель. Центр — `KEY_VOICECOMMAND` (582), вниз — `KEY_VOLUMEDOWN` (114), вверх — `KEY_VOLUMEUP` (115).
- Известный ALSA capture PCM: `hw:0,1`, 4 канала, 16 kHz. Путь звонка обслуживает helper, чтобы основное приложение не конкурировало за аудиоустройство.
- Helper при старте корректно останавливает уже открытые ALSA input/output потоки, если следующая часть аудиосессии не открылась. Временный `device busy` при старте повторяется до 6 раз с интервалом 250 мс, чтобы пережить завершение SFX или предыдущего playback-потока.
- Вызов управляется центральной кнопкой или веб-панелью. В звонке состояние кольца отображается анимированным розовым индикатором; idle состояние тусклое.
- Звук кнопок в idle может выводиться через `aplay`; во время звонка cue передаётся в поток helper. `zen-hover.wav` встроен в helper при сборке.
- Передняя яркость управляется яркостью сегмента часов, диапазон аппаратного значения 0–255. UI/голос используют проценты, приложение переводит проценты в аппаратное значение.

## Разработка и сборка

### Файлы зависимостей

- `Cargo.toml` + `Cargo.lock` — основное приложение.
- `native/gpt-live-host/Cargo.toml` + `native/gpt-live-host/Cargo.lock` — аудио/WebRTC helper.
- Исходники стороннего helper собраны в `native/gpt-live-host`; сохраняйте его лицензию.
- Аудиоресурсы UI SFX и лицензия находятся в `assets/audio/`.
- Веб-страница встроена через Rust include, редактируется в `web/index.html`.

### Кросс-сборка

Цели ABI различаются намеренно: основной сервер — `aarch64-unknown-linux-musl`; helper — `armv7-unknown-linux-gnueabihf` с динамической ALSA/glibc совместимостью. Mini 3 имеет ARM64 ядро, но аудио userspace helper ожидает ARMHF ABI и `/lib/ld-linux-armhf.so.3`. Не меняйте target без проверки ELF, ALSA library/headers и реального запуска на устройстве.

Для локальной сборки установите зафиксированный Rust toolchain, Docker, `cross` и targets:

```sh
rustup toolchain install 1.99.1 --profile minimal
rustup target add aarch64-unknown-linux-musl --toolchain 1.99.1
rustup target add armv7-unknown-linux-gnueabihf --toolchain 1.99.1
cargo +1.99.1 install cross --locked --version 0.2.5
./scripts/build-mini3.sh
```

Скрипт собирает из lock-файлов и при успехе кладёт два файла в `dist/`. Для helper требуется ALSA ARMHF headers/library (`libasound2-dev:armhf`), которые `Cross.toml` устанавливает в build image. После сборки скрипт показывает архитектуру; при ручной проверке `readelf -l dist/gpt-live-host` должен показать ARMHF loader. `dist/` игнорируется Git.

При публикации GitHub Release workflow `.github/workflows/release-mini3.yml` собирает оба бинарника в GitHub Actions, проверяет ELF ABI и прикладывает отдельные бинарники, tar.gz архив с SHA256SUMS и checksum manifest. Workflow использует исходники из тега релиза. Сам workflow пока не запускался: он заработает после того, как изменения попадут в default branch и будет опубликован релиз.

Для быстрой проверки исходников: `cargo check --locked`; helper: `cargo check --locked --manifest-path native/gpt-live-host/Cargo.toml`. Перед установкой соберите релиз обоих targets. Сборка не доказывает исправность на физической колонке; после неё отдельно проверяются запуск сервиса, HTTP и реальный аудиозвонок.

### Развёртывание

1. Завершить активный голосовой звонок.
2. Скопировать прежние бинарники с устройства в backup вне web root.
3. Собрать `dist/gpt-alice` и `dist/gpt-live-host`.
4. Передать оба файла в `/data/opt/gpt-alice/`, выставить executable permission, перезапустить `/etc/init.d/S99zzgpt-alice`.
5. Проверить статус процесса, `server.log`, `/api/runtime`, `/api/voice`; если проверяется голос, сделать короткий звонок и проверить микрофон, playback и завершение.

Не фиксируйте в скриптах адрес устройства или путь личного ключа. Используйте environment variables или явные аргументы. Не деплойте при активном звонке: helper и сервис будут остановлены.

## Секреты, Git и артефакты

В репозитории не должно быть `auth.json`, реальных `.env`, приватных SSH/VPN ключей, токенов, персональных журналов или сетевых идентификаторов домашнего устройства. `.gitignore` исключает runtime-конфигурацию, ключи, логи, `target/` и `dist/`. Cargo lock-файлы, исходники, лицензии, сборочные скрипты и GitHub Actions workflow версионируются. Скомпилированные бинарники распространяются как assets GitHub Release, а не сохраняются в Git.

Перед коммитом:

```sh
git status --short
# Просмотрите список файлов и staged diff перед commit/push.
```

Этот локальный checkout первоначально не имел commits/tracked files и не имел доступной ветки `origin/main`; прежде чем считать проект опубликованным, нужно отдельно восстановить/настроить нормальную Git-историю и проверить содержимое первого commit. Не форс-пушить поверх удалённой истории.

## Скрипты обслуживания

- `S99zzgpt-alice`: управление автозапуском приложения.
- `S99zdropbear`: запуск SSH-сервера на колонке; работает с локальным host key, не содержит приватный ключ клиента.
- `yandex-noupdate.sh`: обратимо блокирует OTA, хранит оригиналы на устройстве. Потенциально затрагивает системные файлы; читать весь скрипт перед запуском.
- `remove_yandex_startup.py`: по умолчанию preview; `--apply` редактирует системный launcher с backup, `--restore` откатывает. Сохранение/отключение `platformd` влияет на функции железа.
- `quarantine_yandex_state.py`: preview по умолчанию; `--apply` переносит выбранные данные аккаунта в локальный backup, `--restore` возвращает.
- `wait_for_root_disable_ota.sh`: ждёт root ADB и запускает OTA script, адрес обязателен.

Это инструменты для обслуживания модифицированной колонки, не стандартный этап обновления приложения. Сначала используйте режим preview/help и убедитесь, что выбран правильный IP/backup. Не выполнять destructive режимы автоматически.

## Известные ограничения

- Веб-панель пока без авторизации; не пробрасывать порт в интернет.
- GPT-Live backend является внутренним/нестабильным; доступ может зависеть от сети, сервиса, аккаунта и обновлений протокола.
- WebRTC peer может кратковременно сообщить о разрыве при продолжающемся разговоре; текущая логика сохраняет активный звонок на transient-состояниях.
- Нужна физическая проверка после каждой сборки, влияющей на аудио, WebRTC, управление LED или стартовые скрипты.
- Не помещайте токены в issue, логи, скриншоты или Git. При диагностике редактируйте account IDs, call IDs и локальные сетевые данные.
