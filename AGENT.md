# GPT Alice — инструкции и контекст проекта

Этот документ — стартовая карта проекта для разработчика и кодового агента. Перед изменениями сверяйте описанные решения с текущими исходниками: приватные backend-протоколы, состояние колонки и сетевые настройки меняются отдельно от репозитория.

## Назначение и границы

GPT Alice — Rust-приложение для принадлежащей пользователю Яндекс Станции Mini 3, используемое как локально управляемая колонка с веб-панелью, экраном/индикаторами, аудио, Bluetooth, расписаниями и голосовыми звонками GPT-Live. Основной сервис работает на самой колонке, интерфейс открывается из локальной сети по `http://<IP-колонки>/`.

- Веб-панель по умолчанию слушает `0.0.0.0:80` и пока не имеет авторизации. Считайте домашнюю LAN доверенной; не пробрасывайте порт в интернет.
- Штатные Wi-Fi, Bluetooth/BlueZ/BlueALSA, аппаратные драйверы и ALSA устройства нужны приложению. Не удаляйте и не останавливайте их как обычный шаг обновления.
- Некоторые функции и GPT-Live зависят от сети, VPN, аккаунта и меняющегося внутреннего протокола Codex. Разделяйте успешную локальную компиляцию, работу API и проверку реального звонка на устройстве.
- Персональная конфигурация колонки не является частью проекта. Не записывайте в Git адрес/MAC устройства, SSH-ключи, VPN-конфиг, OAuth-токены, call ID или персональные логи.

## Рабочие правила

1. Перед работой прочитайте этот файл, `README.md`, относящийся к задаче раздел `PROJECT_OVERVIEW.md`, затем проверьте `git status --short --branch` и актуальный diff.
2. Не затирайте чужие незакоммиченные изменения. Если задача затрагивает существующие изменения, сначала разберите их по файлам и сохраняйте их.
3. Держите приватные параметры вне исходников и команд с открытым выводом. Для локального SSH используйте переменные окружения и placeholder-примеры из README; не добавляйте секреты в документацию.
4. Сохраняйте текущую границу ABI и протоколы между процессами. Не меняйте target/аудиоустройство или приватный GPT-Live wire protocol без проверки исходников helper, совместимости и реального Mini 3.
5. При сетевой/устройственной диагностике сначала собирайте read-only состояние. Перед перезапуском звонка, аудиосервисов, VPN или Colima учитывайте возможное прерывание текущей работы и контейнеров.
6. Сервисные скрипты для отключения OTA/удаления штатного состояния — не часть обычного деплоя. Читайте их полностью и используйте preview/help/backup; применяйте только по явному запросу и к указанному устройству.
7. Не заявляйте, что изменение установлено или проверено физически, если проверены только исходники или локальная сборка. После изменений отделяйте результаты `cargo check`/форматирования, ABI-сборки, установки, HTTP-проверки и пользовательского аудио-теста.

## Архитектура

### Основное приложение

`src/main.rs` создаёт Axum-сервер, runtime-контроллеры, микшер, OAuth, voice session, scheduler, запись wake-word и API. HTML встраивается компилятором через `include_str!`.

- `src/runtime.rs` — кнопки и аппаратный mute, громкость/микрофон, время/NTP, яркость и сцены экрана, Bluetooth, статус runtime и запуск вспомогательных служб.
- `src/indicators.rs` — LED-кольцо и сегменты передних часов; системные индикаторы режимов и временные экранные состояния.
- `src/mixer.rs` — центральное PCM-микширование SFX, GPT-Live и Bluetooth в один выходной поток.
- `src/audio.rs` — взаимодействие с общим выходом и звуковыми событиями кнопок.
- `src/voice.rs` — управление звонками, helper subprocess, JSONL событиями, журналом, командами устройства, поиском, приветствием, ожиданием/тишиной, завершением звонка и передачей контекста.
- `src/oauth.rs` — device-code OAuth, закрытое хранение и обновление токенов.
- `src/storage.rs` — SQLite: все значения шифруются XChaCha20-Poly1305 до записи, ключ `storage.key` хранится отдельно от `state.sqlite`. Не выводить ключ и расшифрованные секреты в логи/API. Не создавать новый ключ при существующей БД.
- `src/telegram.rs` — Bot API, настройки токена/чата, текст/ссылки/картинки по URL. Не повторять отправку автоматически при неопределённой доставке; reqwest URL содержит токен, поэтому сырые сетевые ошибки не логировать.
- `src/web_search.rs` — клиентская делегация поиска через Codex OAuth.
- `src/user_context.rs` — редактируемый профиль долговременного контекста между звонками.
- `src/scheduler.rs` — несколько таймеров и будильников, сохранение расписания и события срока.
- `src/vpn.rs` — управление AmneziaWG и API VPN. Текущий незакоммиченный diff добавляет маршрутный watchdog для host-route endpoint через Wi-Fi; проверьте `git diff`, статус установки и физическую верификацию перед публикацией.
- `src/training.rs` — запись обучающих примеров с микрофонного массива устройства.
- `src/bin/training_recorder.rs` — отдельная утилита/сервер записи с Mac.
- `web/index.html` — основная веб-панель; `web/training.html` — страница записи wake-word примеров.

### Аудиопроцессы и устройство

На Mini 3 основное приложение — AArch64/musl, два аудио-процесса собраны для ARMHF/glibc:

1. `native/gpt-live-host` — сторонняя Rust/WebRTC/CPAL основа с локальными доработками. Открывает микрофон для звонка, ведёт WebRTC, принимает JSON Lines команды в stdin, сообщает события через stdout и передаёт выходной PCM в локальный loopback UDP. OAuth секрет ему не передаётся.
2. `native/audio-sink` — единственный владелец аппаратного ALSA playback PCM `hw:0,0`; принимает interleaved S16_LE PCM из stdin и играет его через mmap. Проверяет смену владельца capture и переоткрывает playback после перехода wake-word ↔ звонок, а также восстанавливается после underrun.
3. `src/mixer.rs` выполняет общую очередь/микширование на основном сервисе. GPT PCM, Bluetooth A2DP capture через оставленный системный BlueALSA и WAV SFX идут в один sink. Голос GPT плавно приглушает Bluetooth музыку и затем возвращает пользовательский уровень.

Физические интерфейсы, подтверждённые для Mini 3:

- `/dev/input/event0` — аппаратный mute и переключатель микрофона.
- `/dev/input/event1` — сенсорная панель: центр `KEY_VOICECOMMAND` (582), громкость вниз (114), вверх (115).
- Capture: `hw:0,1`, четырёхканальный массив микрофонов, 16 kHz.
- Яркость передних часов устанавливается как аппаратное значение 0–255; UI и голос принимают проценты.
- При Bluetooth центральная кнопка переключает play/pause, свайпы `− → центр → +` и обратно дают next/previous. Без Bluetooth центр запускает/завершает звонок. Звук кнопок — отдельный канал 10%, шаг общей громкости — 5 пунктов. Автоматический звонок по wake-word настраивается в панели, но кандидат модели по умолчанию выключен.

Низкоуровневые детали, наблюдения по ALSA и протоколу GPT-Live поддерживаются в `PROJECT_OVERVIEW.md`. GPT-Live endpoint Codex — приватный, нестабильный контракт. Сверяйте команды/events с текущим helper; не отправляйте произвольный `session.*` event.

## Голос, команды и контекст

- Модель получает историю текущего разговора и явные function tools. Для управления колонкой должна возвращаться структурированная команда; локальные эвристики не должны быть единственным способом классификации.
- Rust проверяет аргументы, исполняет команду и возвращает GPT подтверждённый результат. Для чтения состояния есть отдельные `get_*` команды, чтобы не отвечать на основе старого контекста. Список tool-схем смотрите в `src/voice.rs`.
- Web search исполняется приложением по Codex OAuth; ответ привязывается к оригинальному `delegation_id` и возвращается GPT-Live поддерживаемым форматом.
- Временный WebRTC `disconnected`/`failed` сам по себе не доказывает завершение звонка. Не показывайте «потеряно», если session/helper ещё работает; конечное состояние подтверждайте закрытием сессии/процесса.
- Перебивание использует server-side VAD, отмену ответа и очистку только очереди речи GPT в микшере/helper. Не очищайте Bluetooth музыку или SFX вместе с речью.
- Слушать и говорить одновременно — чувствительная к устройству логика. Проверяйте захват микрофона, VAD, interruption, реальное прекращение PCM и продолжение контекста на колонке.
- Общий базовый промпт поведения находится в коде голосовой сессии; профиль собеседника является дополнительной изменяемой выжимкой. Базовые указания поведения не должны зависеть от наличия профиля.
- OAuth, контекст, расписание, настройки устройства/wake-word, Telegram и VPN хранятся в зашифрованных записях `state.sqlite`. Старые JSON импортируются один раз и удаляются после commit; `tools/awg0.conf` остаётся защищённой рабочей копией для системного AWG. База и отдельный `storage.key` не входят в Git или публичные артефакты. Откат до SQLite требует восстановления старых JSON, а не только бинарника.

## Веб-панель и API

Страницы: `/` — панель, `/training` — запись примеров. Основные маршруты перечислены в `src/main.rs`; при изменении API обновляйте панель, код и README/обзор вместе.

- `GET /api/runtime`, `GET /api/indicators`, POST `/api/indicators/*` — состояние, кольцо, передние часы.
- `GET /api/voice`, `/api/voice/silence`, `/api/voice/logs`, POST `/api/voice/toggle` — звонок, idle timer и журнал.
- `GET/POST /api/context` — чтение и изменение профиля.
- `GET/POST/DELETE /api/telegram` — статус без токена, настройки и удаление; `POST /api/telegram/test` отправляет проверочное сообщение в сохранённый чат.
- `GET/POST /api/time`, POST `/api/display/face` — NTP/timezone и сцены экрана.
- POST `/api/bluetooth/power`, `/volume`, `/playback` — A2DP/AVRCP управление.
- `GET /api/vpn`, POST `/api/vpn/power`, `/config` — VPN status и управление конфигурацией.
- `/api/auth/status`, `/start`, `/logout` — авторизация.
- `/api/wakeword`, `/api/training/capture/start`, `/stop`, `/api/training/recordings/{filename}` — wake-word настройка и запись.
- POST `/api/audio/test` — диагностический тест выхода.

Большинство аппаратных вызовов работают только на Linux Mini 3. Локальный `cargo run` на Mac подходит для проверки сборки/неаппаратных частей, но не доказывает работу железа.

## Сборка и проверка

Нужны Rust `1.99.1`, Docker, `cross 0.2.5`, targets AArch64 musl и ARMHF GNU. Lock-файлы есть для основного приложения и обоих helper crate.

```sh
rustup toolchain install 1.99.1 --profile minimal
rustup target add aarch64-unknown-linux-musl armv7-unknown-linux-gnueabihf --toolchain 1.99.1
cargo +1.99.1 install cross --locked --version 0.2.5
./scripts/build-mini3.sh
```

`scripts/build-mini3.sh` собирает три бинарника и размещает их в игнорируемом `dist/`: `gpt-alice` AArch64/musl, `gpt-live-host` ARMHF/glibc, `audio-sink` ARMHF/glibc. `Cross.toml` добавляет ARMHF ALSA dev library. Не меняйте target: совпадение CPU architecture само по себе недостаточно, важны userspace ABI, loader и ALSA.

Локальные быстрые проверки:

```sh
cargo +1.99.1 fmt --all --check
cargo +1.99.1 check --locked --bin gpt-alice
cargo +1.99.1 check --locked --manifest-path native/gpt-live-host/Cargo.toml
cargo +1.99.1 check --locked --manifest-path native/audio-sink/Cargo.toml
```

Не запускайте тесты автоматически, если пользователь не попросил тестирование. Если запускаете проверки, указывайте что именно они доказывают. Кросс-сборка не заменяет физическую проверку звонка/аудио/кнопок.

GitHub workflow `.github/workflows/release-mini3.yml` срабатывает только при опубликовании GitHub Release. Он checkout’ит тег, собирает артефакты, проверяет ELF и прикрепляет отдельные бинарники, tar.gz пакет и `SHA256SUMS`. Для проверки релиза требуются успешный workflow и совпадение checksum. Не создавать тег/релиз при обычной разработке без соответствующего запроса.

## Установка и эксплуатация

Рабочий каталог устройства: `/data/opt/gpt-alice/`. Основной сервис запускается `/etc/init.d/S99zzgpt-alice`; лог — `/data/opt/gpt-alice/server.log`. SSH Dropbear обычно на порту `2222`, но IP и путь ключа задаются для каждого окружения отдельно. Устанавливать следует проверенные бинарники из свежего `dist/` или официального релизного пакета; не заменять бинарник Mac-сборкой.

Рекомендуемый безопасный порядок:

1. Убедиться, что звонок и запись микрофона не активны.
2. Проверить свободное место и наличие `dist`-файлов и их ABI.
3. Скопировать текущие бинарники устройства в backup вне web root.
4. Передать основной сервис и helper в каталог приложения; `audio-sink` разместить в `tools/audio-sink`, а wakeword data — в `wakeword/`.
5. Выставить executable mode и перезапустить `/etc/init.d/S99zzgpt-alice`.
6. Проверить init status, свежие строки `server.log`, HTTP `/api/runtime`, `/api/voice`, `/api/vpn`. Звуковые изменения отдельно проверить звонком и тестом динамика.
7. При проблеме остановить обновлённый процесс, восстановить сохранённые бинарники и снова проверить status/API.

Пример SSH/`scp` команд с переменными и placeholder-значениями находится в `README.md`. Не зашивайте персональные адреса и ключи в скрипты или Markdown.

## VPN и текущая диагностика

VPN использует AmneziaWG userspace (`amneziawg-go`), init-скрипт проекта `scripts/S50awg0` и закрытый runtime-конфиг `/data/opt/gpt-alice/tools/awg0.conf`. `/etc/init.d/S50awg0` на этой колонке оказался read-only; нельзя считать, что его можно исправить обычной загрузкой файла.

Наблюдавшаяся причина сообщения «Интерфейс включён, ожидается рукопожатие»: после долгого простоя host-route к VPN endpoint исчез, вследствие чего endpoint маршрутизировался через `awg0` вместо Wi-Fi `wlan0`. Ручное восстановление endpoint route через DHCP gateway обновило handshake и вернуло статус VPN connected. В приложении локально добавлен watchdog (см. незакоммиченный `git diff`), который должен каждые 10 секунд убеждаться, что маршрут endpoint проходит через Wi-Fi, и восстанавливать его. До новой ARM64 сборки и установки этот watchdog на колонке не действует. Не заявлять, что причина полностью исправлена до проверки потери маршрута и повторного handshake после установки.

Для диагностики использовать `/api/vpn`, `/etc/init.d/S50awg0 status`, `ip route get <endpoint>`, `ip route`, `awg show`/`awg show awg0 latest-handshakes`, журнал AWG и DNS resolution. Endpoint и ключи не копировать в документацию/чат без необходимости. Если AWG поднят, но handshake старый, сперва проверить маршрутизацию endpoint через Wi-Fi и часы устройства; не менять VPN private key/config вслепую.

## Wake-word и обучение

Runtime wake-word находится в `native/gpt-live-host/src/wakeword.rs`; модели и настройки помещаются рядом с исполняемым файлом в `wakeword/`. Переключатель панели управляет автозапуском звонка, но checked-in настройка выключена. Детектор должен освобождать capture до запуска GPT-Live, чтобы не конкурировать за микрофон.

План корпуса, запись с устройства, генерация синтетики, лицензии, локальные данные и статус экспериментальной модели описаны в `training/README.md`, `assets/wakeword/README.md`, `training/assets/ambience/SOURCES.md` и `training/voices/SOURCES.md`. Музыка и большинство corpus/model/report данных — локальные игнорируемые файлы и не должны попадать в Git. Экспериментальный классификатор имеет неприемлемый false-activation tradeoff и не должен включаться по умолчанию или публиковаться как проверенная модель.

## Скрипты обслуживания

- `scripts/S99zzgpt-alice` — запуск/остановка приложения.
- `scripts/S50awg0` — запуск/остановка AWG, подмена DNS/resolver и маршрутизация endpoint; изменяет сетевое состояние.
- `scripts/S99zdropbear` — SSH service script.
- `scripts/yandex-noupdate.sh` — обратимое отключение OTA; сохраняет резервные данные и изменяет системную конфигурацию.
- `scripts/remove_yandex_startup.py` — preview по умолчанию; `--apply` меняет системный launcher с backup, `--restore` восстанавливает.
- `scripts/quarantine_yandex_state.py` — preview по умолчанию; `--apply` перемещает выбранные данные в локальный backup, `--restore` восстанавливает.
- `scripts/wait_for_root_disable_ota.sh` — ожидание root ADB с последующим запуском OTA script.
- `scripts/build-mini3.sh` — воспроизводимая cross-сборка.

Читай `--help` и исходник destructive/сетевого скрипта перед запуском. Предпочитай preview, backup и минимальные обратимые изменения. Такие сценарии не нужны для обычной установки GPT Alice.

## Git, артефакты и секреты

В репозитории хранятся исходники, lock-файлы, UI, лицензии, workflow и воспроизводимые скрипты. `target/`, `dist/`, runtime config/token, ключи, логи, записи пользователя, локальные модели и приватные music assets исключены через `.gitignore`. Релизные бинарники распространяются GitHub Release, а не добавляются в git.

Перед commit/push проверять:

```sh
git status --short --branch
git diff --check
git diff --stat
git diff
git diff --cached --stat
```

Проверяйте staged diff отдельно от полного diff; не добавляйте все файлы командой `git add -A`, пока не проверены runtime/секретные материалы. Не force-push и не переписывайте опубликованные теги без прямого запроса.
