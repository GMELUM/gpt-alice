# GPT Alice для Яндекс Станции Mini 3

Rust-приложение для локального управления колонкой и голосового диалога GPT-Live. Исходники, все три Cargo-сборки, lock-файлы, веб-интерфейс и ресурсы находятся в этом репозитории. Сгенерированные бинарники создаются в `dist/` сборочным скриптом; runtime-ключи и настройки в репозиторий не входят.

## Возможности сейчас

- Локальная веб-панель на `http://<IP-колонки>/`, API состояния и управления индикаторами, передними часами, громкостью, mute, Bluetooth-колонкой и часами/NTP.
- Чтение аппаратных кнопок и mute switch; громкость кнопками меняется шагом 5. В режиме ожидания экран показывает часы, временные состояния возвращаются к часам.
- Вход ChatGPT/Codex через device code flow. Токены зашифрованы в SQLite, не выдаются браузеру и автоматически обновляются.
- Голосовой звонок GPT-Live с физической центральной кнопки или веб-панели. Микрофон и WebRTC обслуживает `gpt-live-host`; GPT, музыка и SFX воспроизводятся общим микшером через `audio-sink`.
- Bluetooth-приём музыки через существующий A2DP Sink/BlueALSA на Mini 3. Веб-панель и голосовые команды включают режим сопряжения, регулируют отдельную громкость музыки и отправляют AVRCP play/pause/next/previous на телефон; во время речи GPT музыка плавно приглушается и затем возвращается.
- Несколько параллельных таймеров (1 с — 99:59) с продлением на секунды, минуты или часы, и одноразовых будильников по локальному времени. Ближайший таймер отображается на часах как `мм:сс`; список, количество, ближайший/самый долгий срок и удаление доступны голосовыми командами. Расписание сохраняется в SQLite. Можно задать текст объявления; пока GPT-Live звонок активен, текст передаётся на озвучивание в него.
- Форма `/training` записывает примеры через встроенный четырёхканальный массив микрофонов Mini 3, сводит PCM в моно 16 кГц и сохраняет WAV с JSON-метаданными рядом с приложением. Файлы можно скачать после каждого дубля. Во время записи звонок и wake-word детектор освобождают микрофон; локальный Mac-рекордер остаётся запасным вариантом.
- Управление устройством выполняется структурированными командами, классифицированными через Codex OAuth, с локальным исполнением Rust-контроллером. Результат передаётся обратно GPT-Live. Поиск в интернете выполняется приложением через OAuth.
- Временные WebRTC-состояния `disconnected`/`failed` не объявляют звонок потерянным сразу: приложение продолжает мониторинг и восстанавливает статус при возврате `connected`. `closed` завершает звонок.

Таймеры и будильники подают трёхсекундный локальный сигнал и включают красную индикацию независимо от GPT-Live. Сигнал использует общую громкость и учитывает отключение звука; при активном звонке дополнительно передаётся текст объявления. Перебивание речи и звуки кнопок не сбрасывают сигнал будильника.

Сохранение часового пояса и NTP через `/api/time` меняет только настройки времени, сохраняя громкость и яркость. Статус Bluetooth обновляется фоновым опросом; чтение `/api/runtime` не запускает системные утилиты. Нефатальные ошибки аудиопомощника записываются в журнал без остановки мониторинга; фатальная ошибка или закрытие транспорта освобождают сессию и микрофон.

На Linux stdout/stderr приложения собираются в `server.log` рядом с бинарником: до 2 МиБ в текущем файле и до 2 МиБ в `server.log.1`. При первом запуске старые журналы сокращаются до последних 2 МиБ каждый. Частые PCM-метрики по умолчанию выключены; для диагностики их можно включить переменной `GPT_ALICE_AUDIO_DIAGNOSTICS=1`.

При подключённом Bluetooth быстрый свайп `− → центр → +` переключает на следующий трек, `+ → центр → −` — на предыдущий. Между соседними касаниями допускается до 300 мс. Свайп не меняет громкость и не нажимает play/pause по пути; одиночные `−`/`+` поэтому обрабатываются с задержкой до 300 мс. Центр переключает play/pause по реальному статусу AVRCP-плеера телефона. Без Bluetooth центр по-прежнему начинает/завершает звонок, а громкость меняется сразу. Разрыв Bluetooth отменяет незавершённый жест. Телефон должен предоставлять AVRCP-плеер; ошибка управления не запускает ИИ вместо музыки.

Звук кнопок идёт отдельным каналом с фиксированным уровнем 10%, независимо от общей громкости, включая 0%, и наличия голосового звонка. Шаг изменения общей громкости остаётся 5 пунктов. Музыка, голос, будильники и диагностический тон продолжают учитывать общую громкость.

## Telegram

В панели есть раздел **Telegram**: токен бота от BotFather, ID чата (число либо `@username` группы/канала), переключатель отправки, сохранение, удаление настроек и кнопка **Отправить проверочное сообщение**. Для личного чата сначала открой бота и нажми Start; для группы/канала добавь бота с правом отправки. Сохранение настроек само по себе ничего не отправляет и не проверяет токен в сети. Пустое поле токена сохраняет прежний секрет; API возвращает только признак его наличия.

Примеры просьб: «Отправь этот текст в Telegram», «Пришли найденную ссылку в Telegram», «Отправь эту картинку в Telegram». Получатель фиксирован настройками панели. Текст и ссылки отправляются через `sendMessage`, картинки — через `sendPhoto` по прямому общедоступному HTTP(S) URL. Генерация картинок и загрузка локальных файлов в эту функцию не входят. Ограничения: 4096 символов для сообщения, 1024 для подписи; ограничения файла проверяет Telegram. Контракт: [Telegram Bot API](https://core.telegram.org/bots/api#sendphoto).

Отправку выполняет структурированная клиентская делегация GPT-Live; отдельный классификатор команд устройства не отправляет сообщения, чтобы два пути не дублировали действие. При сетевой ошибке доставка может быть неопределённой — автоматических повторов нет. Реальная доставка и голосовой сценарий требуют настроенного бота и отдельной проверки.

API: `GET /api/telegram` — статус без токена; `POST /api/telegram` — `{ "enabled": true, "token": "<bot-token>", "chat_id": "<chat-id>" }` (`token: null` сохраняет прежний); `DELETE /api/telegram` — удалить настройки; `POST /api/telegram/test` — отправить фиксированное проверочное сообщение.

## Хранилище и шифрование

`state.sqlite` рядом с программой хранит настройки устройства, расписания, профиль собеседника, wake-word, OAuth, Telegram и конфигурацию VPN. Содержимое каждой записи зашифровано XChaCha20-Poly1305 с отдельным случайным 24-байтовым nonce; имя раздела и версия включены в аутентифицируемые данные. SQLite получает только шифротекст, включая журнал транзакций. Имена разделов и служебная структура БД видны. SQLite встроена в бинарник, системный пакет не нужен.

Случайный 32-байтовый ключ находится отдельно в `storage.key`, права ключа и БД — `0600`. Ключ не выводится через API, не встроен в бинарник и не отправляется модели. Это защищает при утечке одной базы, но не при получении базы вместе с ключом или полном доступе к работающей колонке. Для восстановления нужны **оба файла**; копируй БД при остановленном сервисе и храни ключ отдельно от её копии. Утрата ключа означает утрату доступа к данным; приложение не заменяет отсутствующий/неверный ключ и не сбрасывает существующую БД. Для отдельного окружения можно задать `GPT_ALICE_DATA_DIR`; `GPT_ALICE_CONFIG_PATH` используется только как путь старого файла при миграции.

При первом запуске старые `auth.json`, `config.json`, `conversation_context.json`, `schedules.json` и `wakeword/settings.json` переносятся по разделам в транзакциях и удаляются после успешного commit. Повторный запуск не импортирует старые данные поверх новых; logout не может быть отменён оставшимся старым файлом. Повреждённый файл останавливает свою миграцию, сохраняя исходник. Удаление файла на flash не гарантирует физическое стирание старых блоков.

AmneziaWG пока требует `tools/awg0.conf` для системного init-скрипта: это защищённая рабочая копия `0600`, восстанавливаемая из зашифрованной БД при запуске приложения. Старый `awg0.conf.previous` переносится в зашифрованный раздел и удаляется. Модели, WAV-записи и служебные файлы ОС остаются файлами. Откат на прошивку до SQLite требует восстановления старых JSON из отдельной резервной копии, а не только замены бинарника.

## Сборка

Для локальной сборки нужны Rust 1.99.1, Docker и `cross` 0.2.5. Cargo-зависимости приложения зафиксированы в трёх lock-файлах. Для готовых файлов локальная сборка не нужна: workflow `.github/workflows/release-mini3.yml` собирает бинарники и прикладывает их к опубликованному GitHub Release.

```sh
rustup toolchain install 1.99.1 --profile minimal
rustup target add aarch64-unknown-linux-musl --toolchain 1.99.1
rustup target add armv7-unknown-linux-gnueabihf --toolchain 1.99.1
cargo +1.99.1 install cross --locked --version 0.2.5
./scripts/build-mini3.sh
```

Скрипт собирает основной сервис как AArch64/musl бинарник, а голосовой helper и ALSA sink как ARMHF/glibc. Результат при успешной сборке помещается в `dist/`:

- `dist/gpt-alice`
- `dist/gpt-live-host`
- `dist/audio-sink`

`gpt-live-host` и `audio-sink` используют ALSA userspace Mini 3 (`libasound.so.2`, ARMHF). Sink — единственный владелец аппаратного playback PCM `hw:0,0` (без `default`/`dmix`); он принимает непрерывные S16_LE кадры от приложения по stdin и восстанавливается после ALSA underrun. Для Mini 3 sink использует mmap и автоматически переоткрывает playback при смене потока микрофона: без этого при старте звонка звук мог пропадать. Оба ARMHF бинарника и основной сервис должны находиться на колонке. `Cross.toml` устанавливает ALSA headers/library в build image. Workflow проверяет ELF архитектуры и ARMHF loader до публикации артефактов. Готовность файлов проверяйте по успешному workflow для выбранного тега и наличию SHA256SUMS в релизе.

Локальный запуск панели (аппаратные функции доступны только на Linux Mini 3):

```sh
cargo run
GPT_ALICE_HTTP_ADDR=127.0.0.1:8080 cargo run
```

Локальный сборщик голоса для записи микрофоном на Mac (отдельный сервер, доступен только на localhost):

```sh
sh training/scripts/run_voice_recorder.sh
# откройте http://127.0.0.1:8170
```

Для сборки только основного приложения: `cargo build --release --target aarch64-unknown-linux-musl`. Для helper используйте ARMHF target и доступный ARMHF ALSA sysroot.

## Установка / обновление на колонке

Перед установкой завершите текущий звонок. Укажите адрес и приватный ключ в переменных окружения, чтобы не записывать персональные данные в команды/документацию:

```sh
export MINI3_HOST='<IP-колонки>'
export MINI3_SSH_PORT='2222'
export MINI3_SSH_IDENTITY='/path/to/ssh/id_ed25519'
ssh -p "$MINI3_SSH_PORT" -i "$MINI3_SSH_IDENTITY" "root@$MINI3_HOST" 'mkdir -p /data/opt/gpt-alice'
```

Скопируйте `dist/gpt-alice`, `dist/gpt-live-host`, `dist/audio-sink` и каталог `dist/wakeword/` в `/data/opt/gpt-alice/` через `scp`, затем установите sink в `tools/`, выставьте бинарникам `0755` и перезапустите службу:

```sh
scp -P "$MINI3_SSH_PORT" -i "$MINI3_SSH_IDENTITY" dist/gpt-alice dist/gpt-live-host dist/audio-sink "root@$MINI3_HOST:/data/opt/gpt-alice/"
scp -r -P "$MINI3_SSH_PORT" -i "$MINI3_SSH_IDENTITY" dist/wakeword "root@$MINI3_HOST:/data/opt/gpt-alice/"
ssh -p "$MINI3_SSH_PORT" -i "$MINI3_SSH_IDENTITY" "root@$MINI3_HOST" 'mkdir -p /data/opt/gpt-alice/tools && mv /data/opt/gpt-alice/audio-sink /data/opt/gpt-alice/tools/audio-sink && chmod 0755 /data/opt/gpt-alice/gpt-alice /data/opt/gpt-alice/gpt-live-host /data/opt/gpt-alice/tools/audio-sink && /etc/init.d/S99zzgpt-alice restart'
```

Автоматический вызов по триггеру настраивается переключателем в веб-панели; настройка сохраняется в SQLite и применяется сразу. Пилотная модель отключена (`enabled: false`), пока не подтверждена приемлемая частота ложных срабатываний. Детектор захватывает микрофон только в ожидании и освобождает его перед запуском звонка.

Статус/логи: `/etc/init.d/S99zzgpt-alice status` и `/data/opt/gpt-alice/server.log`. Текущие файлы перед заменой рекомендуется скопировать в on-device backup.

## Секреты и личные данные

- Не добавляйте `state.sqlite`, её журналы, `storage.key`, старые JSON, `.env`, SSH-ключи, логи с транскриптами, файлы из `dist/` и содержимое `target/` в Git.
- OAuth и Telegram сохраняют секреты только через зашифрованное SQLite-хранилище.
- Адрес и ключ SSH задавайте локально; в примерах используйте placeholder.
- Перед push проверяйте staged-файлы и полный diff: `git status --short`, `git diff --cached --stat`.

## Обслуживание устройства

Скрипты в `scripts/` включают init-скрипты сервиса и Dropbear, обратимое отключение OTA, а также инструменты карантина данных/удаления штатных Yandex startup tasks. Изменяющие сценарии имеют отдельные `--apply`/`disable` режимы и могут затронуть доступность устройства. Сначала читайте заголовок и `--help`, делайте backup и не выполняйте их для обычного обновления GPT Alice. Для скриптов, работающих по сети, адрес Mini 3 обязателен и передаётся явно.
